### Suspicious Patterns (investigate)

- **Module-level singleton Supabase client in webhook handler** (`webhook/creem/route.ts:5-14`): The `_supabase` variable is a module-level singleton. In a serverless environment (Vercel), this is generally fine (each invocation may or may not reuse the module). But if the client's connection state goes stale between invocations in a long-running container, requests could fail silently. The Supabase JS client should handle reconnection, but it is worth monitoring.

- **No idempotency protection on webhook handlers**: The Creem docs note that `onGrantAccess` "may be called multiple times for the same user/subscription." The current handler uses `.update().eq("id", orgId)` which is idempotent for the same data. However, if a `subscription.active` event arrives after a `subscription.canceled` event (due to webhook delivery ordering), it would revert the org back to `"active"`. There is no sequence number or timestamp check to prevent out-of-order processing.

- **`metadata?.referenceId as string` type assertion** (`webhook/creem/route.ts:20, 39, 64, 89`): The `as string` assertion is unsafe. If `referenceId` is a number or undefined, the `if (!orgId)` check catches `undefined` and `null` but not `0` or `""` (empty string). While `orgId` being `0` is unlikely with UUIDs, an empty string `""` would pass the `!orgId` check (falsy in JS). But then the Supabase `.eq("id", "")` would match no rows and silently do nothing. Low risk but worth noting.

- **`customer?.email` optional chaining in checkout webhook log** (`webhook/creem/route.ts:26`): The SDK types show that in `checkout.completed` events, `customer` can be undefined (`customer?: CustomerEntity`). The handler destructures `{ customer, product, metadata }` and accesses `customer.email` on line 26 (log) and `customer.id` on line 32 (DB update). If `customer` is undefined, this throws and the webhook returns 500, causing Creem to retry indefinitely. The `onGrantAccess` handler has the same risk but the SDK types for subscription events show `customer: CustomerEntity` (non-optional), so it is safer there.

- **`process.env.CREEM_API_KEY!` non-null assertion** (`checkout/route.ts:4`, `portal/route.ts:4`): If `CREEM_API_KEY` is not set in the environment, this evaluates to `undefined` at runtime despite the TypeScript `!` assertion. The Creem SDK would then fall back to the `CREEM_API_KEY` environment variable directly (see `security.js:126`: `security?.apiKey ?? env().CREEM_API_KEY`). If neither is set, the request goes out with no API key and gets a 403. The error message from the SDK would be generic ("Failed to create checkout"), not "API key missing."

### Root Cause Analysis: The 403 Error

The 403 is almost certainly caused by **Bug #1**: the API key / test mode mismatch. Here is the complete trace:

1. User clicks "Upgrade" or "Starter" button on `/admin/billing`
2. `CreemCheckout` component renders an `<a href="/checkout?productId=prod_56nknnNggE72huMOUqTjfe&units=1&referenceId=ORG_ID&...">` tag
3. Browser navigates to `/checkout?...` (GET request)
4. The `Checkout` route handler in `checkout/route.ts` runs
5. `testMode` evaluates to `process.env.NODE_ENV !== "production"`
6. On Vercel production: `NODE_ENV === "production"` so `testMode = false`
7. SDK creates Creem client with `serverIdx: 0` = `https://api.creem.io` (production)
8. SDK sends POST to `https://api.creem.io/v1/checkouts` with header `x-api-key: creem_test_LsGHbwAPqvAZpLR7QrXFn`
9. Creem production API rejects the test key with **403 Forbidden**
10. SDK catches the error, returns JSON `{ error: "Failed to create checkout" }` with status 500
11. User sees raw JSON error page

If running locally (`NODE_ENV === "development"`), `testMode = true`, SDK hits `https://test-api.creem.io` with the test key, and it likely works -- but only if the product IDs were created in test mode. If those product IDs are production-only, you'd get a 404 instead.

**To fix completely:**
1. Create products in Creem test mode, note their test product IDs
2. Use a separate env var `CREEM_TEST_MODE=true/false` to control the mode explicitly
3. Map product IDs per environment:
   ```typescript
   const PRODUCT_STARTER = process.env.CREEM_PRODUCT_STARTER!;
   const PRODUCT_PRO = process.env.CREEM_PRODUCT_PRO!;
   ```
4. Ensure Vercel production has production Creem API key + production product IDs
5. Ensure local/preview has test Creem API key + test product IDs
